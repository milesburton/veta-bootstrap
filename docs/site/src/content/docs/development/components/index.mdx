This catalogue answers one question: **"Is there already a primitive in the app for what I want to build, or do I need to reach for an external library?"** For the colours, grey scale, and typography these primitives are built from, see the [style guide](../style-guide/).

Every page below imports the **live component** from `frontend/src`. There is no separate copy and no Storybook. If the demo renders, the component works; if it stops working, the docs build fails. That is the point of coupling docs to the app.

## Primitives

- [Badge](badge/): the example primitive this bootstrap ships, showing the pattern end to end.

## Adding a new primitive

1. Make sure the component is **props-only** (no global store, no network call, no framework-specific context that a demo page can't easily provide). If the data dependency is small you can wrap it with a thin demo adapter under `docs/site/src/components/demos/`, but the kitchen sink should only catalogue things a developer can drop in without reading half the codebase.
2. Add the component's source path to the `content` array in `docs/site/tailwind.config.cjs` so its Tailwind classes get generated in the docs bundle, if it uses Tailwind.
3. Create a new page under `src/content/docs/development/components/` following the [Badge](badge/) page as a template: live demo (with `client:load`), props table, import line, source link.
4. Add the page to the **Primitives** list above.
